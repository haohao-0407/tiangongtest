# 森屿：和平殖民地实现

目标：使用天工原生 ECS、渲染、InputSnapshot、资产生命周期和前端 UI，在体素建造底座上实现和平经营循环。战斗、袭击、征召和武器不在范围内。

## Template Disposition

- 保留：game-3d 的官方项目配置、稳定 Engine/Frontend 插件 GUID、UiAsset 身份、程序化 daylight 环境。
- 替换：第三人称场景、角色、物理与指针锁定控制替换为体素区块、俯视相机、体素 DDA 拾取和建造操作。
- 移除：未使用的样例场景/角色/花瓶/碰撞体/材质与对应测试、插件引用，避免样例物体混入游戏。

## 模块

- `assets/voxel/model.ts`：确定性种子生成、方块数组、区块脏标记、事务历史、存档与射线拾取；无引擎依赖。
- `assets/voxel/mesh.ts`：只为可见面创建带硬边法线和顶点色的区块网格。
- `assets/voxel/pcg/rules.ts`：无引擎依赖的墙面、道路边界与高差规则，输出源节点关联的构件、微体素几何和共享步面。
- `assets/voxel/pcg/geometry.ts`：按世界单位 `1/16` 执行局部微体素填充/开洞、可见面剔除和 greedy 网格合并。
- `assets/voxel/pcg/view.ts`：管理独立细节区块、运行时网格资产、构件边界与行走高度缓存。
- `assets/colony/contracts.ts`：居民、资源、订单、研究和建筑的共享数据契约。
- `assets/colony/simulation.ts`：无引擎依赖的经营模拟；时间、寻路、需求、工作和持久化的权威数据。
- `assets/colony/view.ts`：将模拟快照转换为原生 ECS 体素居民、设施、蓝图、农田、物资堆；仅显示，不反向修改模拟。
- `assets/colony/terrain-view.ts`：按 24×24 水平区块显示整地蓝图和笔刷预览，只替换高度或选区变化的区块网格。
- `assets/voxel/runtime.ts`：原生 Engine Plugin，管理相机、昼夜光照、网格资产和输入；将玩家指令交给模拟，发布只读投影。
- `assets/ui/build-ui.ts`：原生 Frontend Plugin 的 UI 控制器，经消息端口与 Engine 通信，在前端保存本机进度。

## 数据与生命周期

新地图使用 250×24×250 有限体素世界与第二版确定性生成器，旧存档保留尺寸和第一版生成结果。居民工作在地表网格上以 A* 寻路，建筑位于地表；不是任意多层三维殖民地寻路。地图查询、寻路缓存、区块边界和相机范围均取实际地图尺寸。

Engine Worker 持有地图和 ColonySimulation；UI 通过端口发送指令并显示快照，只有前端访问本机存储。v2 存档封装地图序列化和完整模拟数据。先在临时世界校验、加载，再替换当前世界，避免损坏存档部分覆盖游戏。

原始方块编辑保留在沙盒工具中，进入时暂停经营模拟。经营施工使用订单、材料和劳动；沙盒保持无限方块与撤销历史。两者共享同一地图，因此沙盒地形编辑会影响恢复运行后的通行性。

地形修改只重建脏区块；居民与普通设施视图共用立方体网格和材质缓存，模拟和显示实体分离。砖墙、道路和已完成石墙由 PCG 网格替代显示。插件 effect 结束时解除消息监听、系统、资产和所有实体。

## 结构级体素 PCG

源语义直接使用 `Brick` 方块、`Road=10` 方块以及已完成的经营 `wall` 建筑。自然石材不自动开窗。沙盒道路工具点击地面顶面时替换命中的地表源格，其余材料仍放入相邻空格；道路编辑同样纳入原事务历史、撤销重做和存档校验。

源地图的稀疏索引只记录砖块和道路。PCG 使用独立的 **8×8 水平细节 tile**，不复用地形的 24³ chunk 脏队列。任意源体素变化会按水平半径两格标记相关细节 tile；这也覆盖非砖/道路方块增删造成的遮挡变化。生成时读取两格邻域，网格只输出本 tile 所有的空间，以保持跨边界的窗台、路沿和台阶连续。建筑类型、位置、占地或完成状态变化同样使附近细节失效。

规则先生成源实体，再执行窗洞减法和窗框/窗台加法；完整源体素由 PCG 替代，普通地形 mesher 跳过砖块和道路，避免原方块遮住窗洞。砖墙每连续两格高生成一个竖向窗间，并根据横向连接、厚度与遮挡保留实体角柱。经营墙高量化为 `29/16`，由同一生成层输出，普通设施视图不再重复画其 cube。

道路规则以外边界生成路沿及约 `4/16` 格宽的人行道，Road–Road 内部边不生成路沿。相邻道路的一格高差在低格内生成八级、每级 `2/16` 高的踏步；铺面和最高踏步高度一致。步面、路沿和窗台边界供玩家碰撞使用，居民行走高度使用同一派生步面缓存。窗内使用内嵌不透明玻璃，保留源砖墙及经营墙的阻挡语义。

`geometry.ts` 只为活跃构件的局部包围范围分配微体素工作缓冲，输出位置都对齐 `1/16` 世界单位。相邻同材质共面面片经 greedy 合并，最终每个有内容的 tile 绑定原生 `MeshAsset`；更新使用 `assets.replace`，空 tile 与卸载时释放实体和资产。每个细节体素不会成为独立 ECS 实体。

存档只记录源方块、建筑和已有游戏状态，不保存派生网格；世界替换、加载或重新生成时清空旧细节缓存，再由有效源节点重建。只读投影中的 `pcg` 提供分辨率、构件计数、最近重建 tile 和构件边界，便于检查源编辑的结果。

当前规则仅处理单一主方向的道路高差连接；多向高路面采用固定方向优先级以避免楼梯互相交叠。道路仍是沙盒材料，没有居民铺路订单，也不支持独立修改窗框/窗台或任意多层建筑。这些边界与操作说明同步记录在 README；具体运行验证见 `validation.md`。

## 等高规划与地基依赖

`level` 指令包含格子集合和目标脚底标高。笔刷在按下时锁定标高、大小与模式，松开时一次提交；预览和已提交蓝图均不改动实际方块。蓝图保存目标、占地、剩余填挖方量、进度及受阻原因。相同目标的重叠规划共用逐格劳动，不同目标在提交前拒绝。

居民的 `terraform` 工作从相邻可达站位每次填或挖一层，成功后更新真实地形与通行性。树木先生成伐木任务，居民站在目标格时先离开。暂停停止劳动；取消只移除剩余工作，不回滚已经挖填的地形。

建筑占地使用完整 `w×d`，`terrainPlanId` 连接地基蓝图。阶段依次为 `preparingTerrain → readyToBuild → constructing → completed`。整地未达标时不创建施工任务，不预约建材；所有地基格达到目标且无障碍后才进入材料和施工阶段。旧建筑的缺省占地迁移为 1×1，已完成建筑保持原状态。

存档保存实际体素、整地计划、居民任务与建筑阶段，加载后从当前地形重新核对待办工作。对内显示使用轻量 `renderState()`；对外只读投影使用快照，静态计划格子集合缓存，避免每帧重复复制大面积选区。
