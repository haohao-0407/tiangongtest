# 任务 18 · 矿点与石料点采集站

## 玩家操作与首版数值

在「建造 → 制作清单 → 采集站」选择一格地表资源点。选址提示显示石料点或铁矿点与剩余量。建成后点击建筑，可以查看剩余量、矿工姓名、取镐或采集状态。资源用尽后面板显示「已采尽」。

- 默认 250 × 250 地图沿用原先 24 条矿脉的位置，按矿脉交替分配，12 条石料、12 条铁矿。同一矿脉内的每一格单独记账。
- 每格石料点初始 24 份石材，每格铁矿点初始 18 份生铁。每批采出 3 份，耗费 8 点工作量，实际用时受居民技能、饥饿、休息与特性影响。比例、储量、每批数量和工作量集中在 `assets/voxel/surface-ore.ts` 的 `MINING_RULES`。
- 每站 8 木材、12 点建造工作。新游戏初始有 140 木材，林夏的背包已有一把石镐。给林夏开启「工作 → 采矿」，或将镐放入木箱，其他有背包空位的采矿居民会前去取用。普通石地形可持镐挖开整地，不出石材。
- 每格储量在采出落地的同一步扣减。搬运员取货后，货物留在其在途栏，到仓才增加库存。耗尽地格保留，拆站后仍可在原格重建，面板保留耗尽状态。
- 旧版 v3 矿脉按原坐标迁移，并重放旧地形编辑，已挖空的格子保持空缺。旧的点地采矿订单退场，存量的落地物和在途搬运仍由原流程处理。v1、v2 原本没有天然矿脉，本版保留这两代旧地图的地形。

林夏带同一把开局石镐，分别在铁站相邻格和石站相邻格工作。缺镐场景把唯一持镐者的采矿优先级关闭，另外两人可以采矿但包内没有镐。通过工作页启用林夏后开始采集。木箱取镐、途中移走镐、旧订单拒绝和角色直接挖点另有模拟断言。

默认种子「森屿-042」另做了完整的自然地图模拟。铁矿蓝图放在 [105,88]、石料蓝图放在 [83,167]。开局仓储石材 110，地上已有 10。两站采尽并送仓后为 144 石材、18 生铁，刚好等于开局存量加上 24 石材、18 生铁。[自然地图读数](./natural-map.json)

## 经理与任务 17 衔接

建筑类型为 `extractionStation`。在 `colony.buildings[].mining` 读取真实的 `resource`、`remaining` 和 `status`。资源分别为 `stone` 和 `pigIron`。选址工具为 `build:extractionStation`，建造卡为 `build-extractionStation`。点击地图上的站体后，在设施面板的 `extraction-station-status` 查看状态。工作页的「采矿」列控制居民就业优先级。规划页旧的直接点地采矿按钮已移除。

## 验收与复跑

以下命令在本地 `game` 目录运行。实机脚本使用一份固定平地和近距离双资源点的开局档，让两座站、施工、取料、搬运、拆除和换日都在游戏内发生。开局石材与生铁均为零，三个建造预算总共 24 木材。天然矿脉的种子复现、比例与旧档迁移另由生成测试覆盖。

```powershell
.\node_modules\.bin\forgeax.cmd project check --json
.\node_modules\.bin\tsc.cmd --noEmit
.\node_modules\.bin\vitest.cmd run --maxWorkers=3
.\node_modules\.bin\forgeax.cmd project play scripts/ore-playthrough.mjs --require-ui --headless true --backend auto --viewports 1280x720 --timeout-ms 480000 --json
```

本地固定源码副本的 ForgeAX 实机验收通过 209 步，1280 × 720 实际成帧，控制台和页面错误均为 0。最终重载后点击原格站体，面板显示「石料点 · 剩余 0 · 已采尽」。[引擎记录](./play.json) · [原格重建并读档截图](./12-rebuilt-and-reloaded.png)

项目检查、类型检查通过，完整回归通过 29 个测试文件、241 项测试。采集测试另覆盖工人实际从木箱取走唯一的石镐，采集中移走石镐后余量保持，旧订单读档时作废，旧货保留。另在余量 15 时拆掉铁矿站、保存、读档并在原格重建，余量仍为 15，原先落地的 3 份生铁和库存读数保持一致。

本地修改涉及地图生成与矿纹、建筑定义与模型、模拟与读档、选址与站点面板，以及对应测试和实机脚本。右上角缺料提示由任务 17 维护。
