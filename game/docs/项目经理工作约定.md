# 体素项目经理与执行对话

用户决定玩法和排期，经理在本对话维护待办、提出建议、收集验收结果。执行对话根据用户批准的任务卡工作。[本轮任务卡](./项目排期-2026-11-27.md)

## 经理怎样准备一轮排期

1. 用本机飞书 skill 以用户身份读取配置表，记录查询日期、修订号、页签和行号。先读总览，再读涉及同一玩法的表。可用 `wiki +node-get` 获取表格标识，用 `sheets +workbook-info` 查页签，用 `sheets +csv-get` 读实际内容。遇到凭据锁时，按本机权限流程重试同一只读命令。
2. 查现有资源 ID、玩法入口、测试和当前工作区改动。分别记录用户决定、飞书描述、代码行为和实机证据。表里的“未实现”需要核对。功能已实现但缺图标时，把图标单独列为美术项。
3. 给用户一份按先后排序的短清单。每项写清玩家能得到什么、依据、验收方法，以及要由用户决定的玩法。此时状态为“待批准”。
4. 用户点名同意后，用批准的任务卡创建新的项目对话。第一条消息写明任务编号、目标、允许修改的位置、验收条件，以及交付物。记录对话标题和派发状态。执行人涉及相同代码或表格区域时，由经理安排先后。
5. 经理检查交付证据和改动范围，再反馈给用户。区分本地工作区、已提交版本和已发布版本。飞书写入任务要回读修改过的单元格。未完成的实机验收继续列在待办。
6. 每轮手头工作处理完，经理主动列出接下来需要用户拍板的玩法或排期。每项写清建议及其对玩家的影响。已经决定的规则沿用，待选提案获批后再派发到侧栏项目对话。

## 新对话接单时

先读获批任务卡和项目约定，再核对当前代码与表格修订。冷藏改动可能只存在于当前工作区，先检查五个相关文件及差异，再选择验证基线。若工作环境缺少这批改动，向经理报告差异，避免在旧版上重复实现。执行时保护已有修改。

交付时写明完成的玩家操作、修改的文件或飞书单元格、验证方式和结果。附上可重复的步骤或截图。如果发现另一个玩法缺口，记录为候选事项交经理整理。

用户要求使用项目侧栏可见的新对话。执行对话保留最终回复，同时把摘要发回「体素项目经理」。本轮用户在经理对话明确授权直接回报，可用 read_thread 核对原话，再用 send_message_to_thread 向本机线程 `01a20b1d-a549-7fb2-8de1-0b8f9329a551` 发送一次完工报告。说明实机验过哪些操作、截图和记录在哪里、还有哪些限制。发送未成功时，把报告留在执行对话并注明发送结果，便于经理取回。
