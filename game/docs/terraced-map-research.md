# 自由地形与等高笔刷：ForgeAX 地图实现方案

日期：2026-11-14。对象：`D:/tiangongtest/game`，`@forgeax/engine` 0.4.19。

状态：设计方案，已结合当前源码审计与用户修订更新；尚未修改游戏逻辑或进行运行验收。本文替代此前以固定低台地约束玩家的方案。

## 1. 已确认的设计方向

核心玩法改为 **玩家指定目标地形，居民按蓝图施工**。地图初始形态提供经营起点，玩家可以自由把区域填高、挖低和整平。

用户确认：**建筑放置时自动附带整平蓝图**。玩家可以在不平整地形上先放建筑计划；系统先准备地基，再开始建筑施工。

- 等高笔刷把选区所有格子的目标地面设为同一个高度，支持涂抹、矩形框选、取样高度与直接输入高度。
- 取消“只允许基准层和高一级台地”“每图只能有一两片台地”“只能在预设通道处改造”等编辑硬限制。
- 河岸、河床、岩石地面均可纳入填挖计划，不再按地貌类别禁止编辑。
- 初始地图仍可默认平缓、预留开局空间；原先的平地比例、18×18 起始区和缓坡尺寸仅是可选生成参数，不限制玩家改造。
- 已取消厚岩顶、洞内建造及剖顶系统。自然地形使用露天的单表面模型；普通建筑人工屋顶由建筑系统独立处理。

“自由编辑”意味着计划可放在各种地形上，不等于居民能瞬移、现有建筑自动消失或所有工程立即完成。不可达、占用或积水变成可见的施工前置条件，而不是按地形种类拒绝蓝图。

## 2. 等高笔刷交互

### 操作流程

1. 选择“等高整地”。默认目标高度取当前地面，可点击取样或直接输入。
2. **开始一笔后锁定目标高度**，跨过山坡或河岸不会重新取样。高度取自逻辑地面，不取树冠、矿石顶或桥面；取桥面标高应是明确的独立取样选项。
3. 拖涂或框选范围，实时显示目标平面：高于目标的部分标“挖”，低于目标的部分标“填”，已经相等的格子不生成工作。
4. 显示选中面积、挖方量、填方量、占用/积水/施工可达性。填挖各自显示，不能只显示净方量而隐藏大量工作。
5. 松开提交一个整地计划，实际地形保持原样，由居民逐步施工；一次笔画对应一次计划撤销操作。

同一笔经过某格多次只产生一个目标，不累加挖填深度。目标高度更改作用于后续笔画或显式选中的既有计划，不悄悄改写全部历史蓝图。

设当前高度为 `h[i]`、锁定目标为 `H`、每格水平面积为 `A`：

```text
挖方量 = Σ max(h[i] - H, 0) × A
填方量 = Σ max(H - h[i], 0) × A
```

蓝图表达严格等高的最终意图，不使用“刷几次才接近目标”的软笔刷强度。施工进度可以逐渐接近目标。平滑坡面或连坡工具可随后增加，其功能与等高笔刷分开。

界面可参考 [Unity 官方 Set Height 工具](https://docs.unity.com/en-us/engine/6000.0/manual/creating-environments/script-terrain/terrain-tools/terrain-set-height) 的数值高度、地面取样和抬高/压低交互；本方案增加的是经营游戏的蓝图、工作队列和施工依赖，不是接入 Unity Terrain。

### 成本建议，尚未由用户指定

首版建议普通土方仅消耗工时，挖方和填方采用可调的单位体积工作量，不强制玩家逐格搬土或先采集填土材料。采集树木、石块和矿点仍走各自的资源流程。需要土方物流时再扩展供料/产出账本，避免首版把改造自由度变成材料管理负担。

## 3. 建筑自动附带整平蓝图

建筑蓝图有“目标底标高”和完整足迹。默认从放置锚点的地面取高度，预览中可以调整；同一栋建筑锁定一个高度，不随足迹中各格变化。

```text
放置建筑蓝图
    ↓
清理足迹中的资源 / 等待已有设施处理
    ↓
各格填挖到建筑目标高度
    ↓
检查足迹同高、可承载、干燥和施工可达
    ↓
预约建筑材料 → 建筑施工 → 完工
```

- 在高低不平的地面上放置建筑，应成功创建建筑计划及对应整地计划，而不是先报“地形不平”。
- 建筑阶段为 `preparingTerrain → readyToBuild → constructing → completed`。受阻原因单独记录，条件恢复后继续推进。
- 建筑足迹已平整时跳过整地；完成标准基于真实地形，不能把目标预览当作已经平整。
- 涉水位置同样允许计划；地基低于实际水面时显示“等待退水/调整地基高度”，不暗中删除水。调整高度会同步更新附带整地计划。
- 已建建筑或桥不会因笔刷经过被自动拆除。该格计划显示占用，等待玩家处理已有设施后施工；不删除整片选区。
- 自动整平默认只覆盖建筑足迹。可额外显示出入口接坡建议，但不能悄悄扩大笔刷范围或修改周边私人规划。
- 出入口在施工和使用时都需要连接实际可达地面；单纯把足迹抬高不等于居民已经可以进入。

当前建筑定义大多单格，因此真正跨高差建筑需要先增加足迹数据，不能只在现有单格检查后增加一个整地按钮。

## 4. 取消编辑限制后的空间规则

### 高度与边界

不再只允许 0/+1 两层。目标高度在可配置的世界存储范围内自由选择；现有 `WORLD_HEIGHT = 24` 是当前存储与碰撞实现的技术范围，不是新的玩法高度上限。首轮可以显示并校验实际可支持范围，扩大范围需同时更新数据、相机、碰撞及存档，不能宣称无限高度。

仍使用每个 `(x,z)` 一个地面高度的模型，桥面可作为其活动表面；不因此增加悬空岛、地下隧道或上下双层经营。地表高度可以变化很多级，不需要预先创建若干固定台地区域。

### 行走与坡面

取消“异高相邻格只能经预设坡道”规则。根据当前实际几何与角色能力动态生成通行边：可跨的小落差自动连通，连续缓坡按真实坡度和净空判断；无法直接通过的大落差由玩家整地、铺阶梯或修坡解决。

等高笔刷可能在边缘留下陡坎，系统可以预览断路或建议入口，但不阻止玩家创建该计划，也不默认自动平滑选区外的地形。蓝图和任务允许等待通路，不能让居民忽略陡坎直接穿越。

### 建筑和居民占用

居民能短暂停留在施工格时，执行前先要求其移到安全站位，不把临时站人变为永久禁止编辑。居民正在站立的支撑不能在同一提交中直接消失。现有建筑占用则形成等待条件；自动附带整地不代表自动拆除既有建筑。

## 5. 当前地形、目标地形和施工进度分开

新模式以逻辑地表、资源和完成建筑为实际状态的权威。渲染网格、导航和细节几何由实际状态派生；蓝图另存目标，不直接写进实际地形。

```ts
// 本项目拟新增的契约，不是现有 ForgeAX API。
interface LevelPlan {
  id: string;
  revision: number;
  cells: CellId[];
  targetY: number;                   // 笔画/建筑锁定标高
  origin: 'brush' | 'building';
  ownerBuildingId?: string;
  status: 'active' | 'paused' | 'cancelled' | 'completed';
}

interface CellEarthwork {
  cell: CellId;
  targetY: number;
  revision: number;
  consumers: string[];               // 使用此目标的笔画/建筑计划
  completedWork: number;
  blockedReason?: string;
}

interface TerrainCell {
  floorY: number;                    // 已完成的真实地面/河床
  groundKind: GroundKind;
  resourceId: number | null;
  waterVolume: number;               // 与地形独立的实际水量
  deckId: string | null;
}
```

各格权威目标通过 `CellEarthwork` 索引统一；同一格同时只能有一个有效整地目标。依赖引用标识加版本，防止旧任务在目标变更后继续提交。

- 同目标重叠：合并实际工作，登记多个使用者，不重复计工或扣料。
- 不同目标重叠：预览显示冲突。纯手动计划可用明确的“替换该处计划”操作更新；涉及建筑地基时必须同步调整该建筑标高或解除它的依赖，不能静默覆盖。
- 局部替换时，将对应格从旧计划的 `cells` 和旧使用者引用中移除，必要时拆分旧计划，再建立新目标引用；旧计划只等待仍属于自己的格子。剩余为空的旧计划标记取消并注明已替换，防止永远等待已经失效的旧目标。
- 暂停/恢复按使用者记录；只要还有活跃计划依赖同目标工作，该工作继续执行。全部使用者暂停时才暂停共享工作。
- 目标变化后，从当前实际高度重新计算剩余填挖量。已经完成的工作不会再按最初高度重复计算。
- 取消计划只撤销未执行意图；已经完成的地形不会瞬间回滚。恢复旧高度应另建反向整地计划。
- 取消建筑可撤掉只属于它的未完成整地；共享整地仍有其他使用者时继续保留。
- 待施工蓝图可以撤销/重做；已经执行的操作采用补偿计划，不把“撤销 UI 指令”和“恢复整个世界历史”混为一谈。

## 6. 居民如何逐步施工

整地是一个可保存的批量计划，派工时按可达边缘展开小工作单元，不必一次创建“选格数 × 高差”的全部任务。

- 挖方逐层从顶部向目标推进；填方从实际承载面向目标推进。一个工作单元的提交是原子的，但整片区域分多步完成。
- 工人站在当前真实可达位置施工，不要求先站到未来平台上。高差较大时，需要施工前沿、临时阶梯/脚手或可行的接坡，不能无条件从底部操作无限高度。
- 临时工程仅在已有授权的计划区域内安排；若必须占用选区外空间，应显示待补的施工通路而不是擅自改地形。
- 检查可撤离路径，避免先挖断唯一出口或先填死通道；没有安全顺序时显示具体阻塞原因，不靠反复重派任务循环。
- 每次提交前复核目标版本、工作站位、人物/建筑占用和水状态；提交后更新地面、导航、任务站位与局部网格。
- 工作优先级同时考虑计划优先级、可达距离和前置任务；建筑施工只能在整地依赖全部满足后领取。
- 施工开始和最终完工时都复核真实足迹，防止施工中另一笔整地改变地基。

建议首版普通土方只消耗工时，可减少资源互锁，这项成本选择尚未由用户确认。以后若引入填土物资，应按施工阶段预约，避免建筑预留全部石料后整地等待同批材料。保存已消耗和未消耗预约，取消时只退后者。

## 7. 河床可编辑时的水体处理

原来的“固定水块 + 不允许改河床”方案不再满足自由整地。填河、挖岸、挖池都可以规划，施工后水状态必须随地形变化。

建议第一版使用 **二维格子水量 + 邻格流动** 的简化模型，不要求完整三维流体：

- 每格保存非负水量，地面高度和水量共同得到水面标高；邻格间交换等量水，流出量不能超过当前可用水量。
- 水跨越格边前检查两侧地面形成的坎高，桥面不等于堵水的地面；有河流源或地图出口时，水量变化由显式源/汇记账。
- 填高水底不会凭空删除水：保留水量后水位升高，再向可流通邻格转移。挖低干地不会凭空生成水，连通现有水体后才可进水。
- 地形逐步提交后推进有限步水体更新，并使受影响的岸线、导航和建筑准备状态失效；有持续进水时建筑可继续显示积水阻塞。
- 地形变化影响的水域可以跨很多区块，不能只刷新一个被刷到的格子；需要脏区域队列和固定每帧预算。

流动速度、稳定性和大面积改河的开销需要原型验证。不能把“蓝图允许填河”宣称为已经具备水利模拟；这是开放水域改造后必须配套实现的部分。

## 9. 生成、保存与旧模式

生成器只决定初始地形，不负责维持永久平地比例或台地数量。默认仍以便于开局为目标，玩家的整地结果优先，不得在后续生成/装饰时被重新抹平。

新地图保存模式标识、schema/generator 版本、真实地面/水量/资源/建筑、整地计划、有效格目标、依赖及工作进度。读档检查引用有效、依赖无环、同格目标唯一，重建导航与显示缓存。

旧档继续用旧生成算法恢复，不能替换生成逻辑却仍沿用旧版本号。旧任意体素沙盒保留 legacy 模式；新模式沙盒可以即时提交同一地表编辑接口，经营模式则提交蓝图。两者共用空间查询，避免出现两套互不一致的权威高度。

新任务类型需兼容旧居民的技能/工作优先级默认值。原高度、任务数量和路径搜索预算中的硬编码应逐项核查；大选区需要批量与按需派工，不能静默丢弃超限格子。

## 10. 分阶段实现与验收

| 阶段 | 交付内容 | 核心验收 |
| --- | --- | --- |
| A：计划与预览 | 取样、输入高度、涂抹/框选、填挖预览、计划索引 | 一笔锁定高度；实际地形不变；重复经过不叠加工量；填挖统计正确 |
| B：真实整地 | 居民分步填挖、可达站位、取消/改目标、局部刷新 | 最终真实高度等于目标；无悬空居民；大高差/断路能报告阻塞并恢复 |
| C：建筑联动 | 完整足迹、自动整平依赖、分阶段施工 | 不平地上能放建筑；整平前不能开工；共享计划与取消不重复计工退款 |
| D：水域改造 | 水量与邻格流动、填河/挖岸状态更新 | 填河不删水、干地开挖不生水、破岸后流入、积水建筑正确等待 |
| E：存档与范围压力 | 完整恢复、旧档兼容、大选区和细节重建预算 | 施工半途重载一致；原地图全部可规划；超预算队列有进度不丢工作 |

有区分力的测试用例：

1. 在高低交错的选区设定同一高度，分别检查挖方/填方/不变格及实际完成结果。
2. 拖过不同高度时锁定值不漂移；连续画过同格不会重复生成整地工作。
3. 在坡地放多格建筑，自动产生必要整地，所有足迹满足后才允许开始施工。
4. 手动整地计划与建筑附带整地同高重叠，取消一个后另一个继续；局部替换正确移除旧依赖，不同标高不产生反复填挖。普通建筑足迹仍不能相互重叠占用。
5. 工程中途改高度、取消、存读档，剩余工作按真实地形继续，已完成地形不瞬间回滚。
6. 填挖唯一通道或临时站人格，先安排撤离/等待；条件变化后能恢复，不无限重派。
7. 填河和挖干池验证水量变化来源，局部水位变化能传播到受影响区块。
8. 用当前整张地图创建计划，验证分批派工、界面响应和网格更新开销；性能目标由原型测量确定。
