# 和平殖民地经营：机制范围与验收

研究日期：2026-11-11。本文是实施建议和验收契约，**不是当前版本完成清单**；实际完成状态须以最终源码、自动检查和引擎内操作证据为准。

目标是在现有体素 3D 地形与建造基础上，尽可能保留 RimWorld 基础经营的系统联系。排除战斗、武器、防御、袭击和暴力精神崩溃；压力来自物资、劳动分配、需求、环境与疾病。本文不展开 DLC，也不承诺复刻全部原作内容或精确数值。

## 官方资料与采用范围

- 官方介绍确认了居民需求与情绪、背景影响能力、关系、健康、生产材料、贸易、程序化环境及叙事事件等系统。这里采用系统方向，不把官网概述当作全部细节的技术规格。[RimWorld 官方介绍](https://rimworldgame.com/)
- 地面物品、仓储过滤和仓储优先级是官方早期明确引入的物流机制；值得保留“居民搬运实物”的因果关系。[Ludeon：Alpha 1](https://ludeon.com/blog/2014/01/alpha-1-released/)
- 娱乐、日程和技能学习存在联动；官方说明娱乐来源可有不同种类，居民可按日程睡觉、工作和休闲。[Ludeon：Alpha 10](https://ludeon.com/blog/2015/04/rimworld-alpha-10-joy-system-released/)
- 室内外温度、季节、寒潮热浪、加热制冷以及食物冷藏是经营链的一部分。[Ludeon：Alpha 8 官方日志](https://ludeon.com/blog/page/18/?no_redirect=true)
- 生产建筑、燃料设施、商队、研究树和研究台是基础经济与科技扩张的组成部分。[Ludeon：Alpha 13](https://ludeon.com/blog/2016/04/alpha-13-released/)

上述更新日志用于核实机制来源，属于历史资料，不代表当前版本所有细则。以下具体数量、算法、优先级和取舍均是本项目的实施建议。未采用论坛玩家发言作为官方规则依据。

## 机制对应表

“完整核心”表示把该行限定范围内的输入、行动、资源变化、失败原因和保存恢复做成闭环，不表示完整还原原作系统。“简化”表示保留主要因果关系，并明确减少模拟维度。

| 机制 | 建议范围 | 可执行实现 | 最小验收与边界 |
| --- | --- | --- | --- |
| 居民需求与情绪 | 完整核心；简化情绪内容 | 每人独立饥饿、休息、娱乐；通过实际进食、睡眠、休闲恢复。情绪由可见原因组成，例如饥饿、露宿、舒适用餐；低情绪可短暂停工或独处。 | 食物不足时先报警，吃到一份食物后库存减少且该居民饥饿改善；睡床比露宿恢复更好；增加娱乐能改善对应情绪原因。需求不能仅靠全局定时自动补满。 |
| 技能、特性与背景 | 简化 | 建造、种植、烹饪、采矿、医疗、研究、社交等少量技能；劳动获得经验，技能影响速度或产出。特性从少量有真实效果的选项中生成；可保留个别工作禁忌。 | 同条件下熟练者完成对应工作更快；至少一个特性真实改变需求或效率；不可工作类别在调度和界面均被禁止。暂不做完整背景库、技能衰减、复杂激情系统。 |
| 工作优先级与日程 | 完整核心 | 每人每类工作设 0=禁用、1–4=从高到低；同级采用公开且固定的类别顺序，再按路径成本与任务 ID 决定。危险需求优先自救；支持工作、睡眠、娱乐、自由时段。 | 调高种植优先级后居民确实先种植；禁用搬运后不再领搬运任务；两人不重复占用同一目标；不可达、缺料或被占用时显示原因并转做其他任务。该排序是本项目明确约定，不声称逐项复制原作内部排序。 |
| 仓储与运输 | 完整核心 | 地图物品堆、容量、分类过滤、仓储优先级、搬运任务和物品预留。搬运者先到源位置取货，再运到可达且有空间的目标；高优先级仓储可吸收低优先级库存。 | 错误过滤不收货；仓库满时物品留在原地并提示；搬运前后物资守恒；途中目标失效会重选或安全放下。全局资源栏只能汇总实物，不能代替物流。 |
| 农业与烹饪 | 完整核心；少量作物和配方 | 种植区→播种→随时间生长→收获→搬运；生长受土地、光照和温度影响。灶台订单消耗原料与工时，支持制作 N 份或维持库存 N 份。 | 未成熟不能正常收成；极端低温停止或损害生长；厨师到灶台且有原料才产出餐食；达到订单上限停止生产，消耗后恢复。首期不增加灌溉等未经需求确认的新系统。 |
| 采集与建设 | 完整核心 | 树木、矿物可标记采集；建造按蓝图→送材料→施工→完成；保留体素编辑作为规划或沙盒工具，经营模式必须支付材料与劳动。拆除返还明确比例材料。 | 缺料蓝图不会凭空完成；工人可达工作位置；取消蓝图释放预留并退回未消耗材料；封死路径后安全停工；经营模式不能通过直接放方块绕过成本。 |
| 房间与设施 | 简化 | 在可行走地表层做围合检测，配合明确屋顶状态；区分室外、卧室、厨房、仓库、工作室。床、桌椅、灯和清洁影响居住与工作。 | 完整围合且有屋顶才算室内；拆墙或拆顶会重新判断；床有使用者，不会多人同时占用；房间检测变化立即影响舒适或温度。首期不承诺任意三维洞穴、多层楼和完整房间评分。 |
| 电力与温度 | 简化 | 先做可见发电、耗电和电池收支，设施根据可用电量启停；室外随昼夜、天气和季节变化，室内使用集中温度模型，加热或制冷消耗电力。食物腐败受存放温度影响。 | 电池不会负数或无来源充电；供电不足会停机并说明原因；断电后室温渐回环境值；冷库内食物比常温保存更久。若使用全殖民地共享电网，必须在 UI/说明中标注；未实现导线连通就不宣称完整电网。 |
| 健康与医疗 | 简化 | 健康、疾病进度、体力/行动效率；饥饿和极端温度造成健康压力。病床休息与医生护理消耗药材，医疗技能影响恢复。 | 患病者实际减速或停工；医生前往病人并消耗药材；治疗改善恢复且缺药有反馈；健康问题能在居民面板解释。暂不做逐器官损伤、手术、义体、成瘾和复杂免疫竞争。 |
| 研究与生产解锁 | 完整核心；小型科技树 | 选择研究项目，居民在研究台投入工时积累进度；设置明确前置关系，完成后解锁具体建筑、配方或效率升级。建议先做 4–6 个节点。 | 无研究员或无可用研究台时不自动增长；切换研究保留进度；未满足前置的项目不可开始；完成后确有新内容可建或生产；存档重载不重复发放解锁。 |
| 贸易 | 简化 | 友好商人定期来访，有限商品与资金；选定居民谈判，社交影响价格；买卖按一次交易原子结算。 | 买不起、数量不足或商人离开时不能成交；买卖后双方货物与货币守恒；购买物品进入地图可搬运位置。暂不做世界地图商队、派系外交、轨道交易或动态市场。 |
| 天气、季节与和平事件 | 简化 | 晴雨、冷暖季节、寒潮/热浪、小型疾病或友好访客；使用固定种子、冷却和互斥条件控制事件。所有事件有实际模拟影响与结束条件。 | 雨天/寒潮真实改变至少一项生长、温度或发电参数；事件提示可定位原因；结束后撤销临时效果；保存恢复保留事件剩余时间与随机状态。没有实质影响的提示只算信息通知。 |

## 建议实施顺序

1. **生存生产闭环**：居民、需求、时间速度、任务调度、采集、实物堆和仓储、材料建造、种植烹饪、床与餐桌。先确保一座小营地能够自主运转。
2. **环境与扩张闭环**：围合房间、清洁、供电、温度与腐败、基础医疗、研究解锁、贸易与和平事件。
3. **加深人物和内容**：更丰富的情绪、少量社交关系、服装制作、动物饲养等另行扩展；本表未包含的系统不自动视为已交付。

这三个阶段是排序建议；完成声明应逐行记录“完整核心 / 简化 / 未实现 / 未验证”，不要用总体百分比掩盖缺项。

## 必须共享的数据约束

- 调度统一使用任务状态与资源预留；物品、工作台、床、地块不可被互斥任务重复占用。任务取消、居民离开、对象销毁时释放预留。
- 移动必须检查地形和路径，作业必须检查到达工作位置；模型朝目标滑动但穿墙，不能算已完成寻路。
- 需求、劳动、植物、天气、研究等使用同一模拟时间；暂停全部停止，倍速按相同比例推进。随机事件使用可保存的独立随机状态，不借渲染帧率决定结果。
- 存档保存地图变更、居民、物品堆、区域、建筑、订单、科技、时间和事件。加载后重建索引与任务预留，不重复生成物资或重复结算交易。
- 界面展示当前行动及停工原因：缺材料、不可达、优先级禁用、无人可做、床位不足、无电等。资源栏区分总量、已预留和可用量。

## 可验收的最小演示

在正常游戏入口建立一个固定种子的 3 人营地，使用真实界面与指令完成以下操作；测试不得预先伪造完成状态。

1. 划定木材仓储并标记树木，观察居民采集、携带、入库；截取物流状态和实际场景。
2. 放置卧室与厨房蓝图，观察材料不足、送材、施工、房间判定和居民睡眠；撤销一个未完成蓝图，检查无资源损失或复制。
3. 设种植区和餐食订单，等待生长、收获、烹饪、进食；改变一名居民工作优先级并观察行为变化。
4. 建发电与温控设备；通过正常设施开关断电，验证供电、室温和食品保存的变化。
5. 完成一个研究解锁，用友好商人完成一次买卖，并处理一次自然产生的和平环境/健康事件。
6. 保存并重载，核对居民需求、实物库存、建筑、科技、订单和事件持续状态；再次执行核心操作。

每项保留可读取的状态断言及一张命名截图。纯模拟测试至少覆盖资源守恒、任务争抢与取消、不可达目标、作物与餐食守恒、暂停/倍速、存档往返。最终还要完成项目要求的引擎内操作与视觉检查；测试通过或页面能打开，不单独代表玩法已经验收。
