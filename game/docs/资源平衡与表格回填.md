# 建筑材料与采集产量

游戏从 [resource-balance.json](../assets/colony/resource-balance.json) 读取全部 56 种建筑的用料、每格树干产木量，以及石铁矿格的储量和单批产量。可直接编辑该文件，也可用 Python 3 把策划表回填到同一文件。保存后重新启动游戏或重新构建发布包。

## 飞书整页回填

把「建筑」和「资源」两个工作表分别导出为 UTF-8 CSV，保留前两行和原列顺序。若导出的是一个 Excel 工作簿，可在 Excel 中分别选中两页并另存为 CSV UTF-8。两页的表头均在第 2 行，第 3 行起为数据。

| 工作表 | ID | 数值列 |
|---|---|---|
| 建筑 | B 列英文建筑 ID，每个建筑一行 | O 木材、P 石材、Q 木板、R 石砖、S 生铁、T 钢铁、U 布料、V 零件。无消耗填数字 0 |
| 资源 | B 列英文资源 ID | wood 行 J 填每格树干产木量。stone 与 pigIron 行 K 填每矿格总储量、L 填每批采出。其余交叉项可留空 |

在游戏目录运行以下命令。第一条检查两张表并报告是否与当前游戏一致，第二条把通过核对的内容写入配置。少行、重复 ID、缺材料列及无效数量会报错，并保留原配置。

```sh
python scripts/resource-balance.py check 建筑.csv 资源.csv
python scripts/resource-balance.py import 建筑.csv 资源.csv
```

## 从游戏导出精简表

```sh
python scripts/resource-balance.py export 建筑精简.csv 资源精简.csv
```

精简建筑表首行是 `id,wood,stone,plank,stoneBrick,pigIron,steel,cloth,components`，资源表首行是 `key,value`。可直接编辑导出的两份 CSV，用上面的 check 和 import 命令读回。产木、储量、批量填正整数，建筑材料可填 0。篝火晚会广场在本轮为免费建筑，八个用料格均填 0。

## 首轮用量

| 每座或每格 | 原值 | 现值 |
|---|---|---|
| 木墙 / 石墙 | 5 木 / 5 石 | 2 木 / 2 石 |
| 木地板 / 木门 | 3 木 / 8 木 | 1 木 / 3 木 |
| 栅栏 / 牧场门 | 3 木 / 3 木 | 1 木 / 2 木 |
| 砖墙 | 4 石砖 | 2 石砖 |
| 石门 | 5 石砖＋2 石 | 3 石砖＋1 石 |
| 温室墙 | 4 木板＋4 钢铁 | 2 木板＋2 钢铁 |
| 3 格 / 4 格树干 | 18 木 / 24 木 | 9 木 / 12 木 |
| 新石料点 | 每格 24，每批 3 | 每格 12，每批 2 |
| 铁矿点 | 每格 18，每批 3 | 每格 18，每批 3 |

按一圈 16 格的房屋外墙举例，15 格木墙加 1 扇门过去需要 83 木，现需 33 木。只砍 3 格高的树，分别需要 5 棵和 4 棵。一个新石料格采尽可建 6 格石墙，需采 6 批。

## 存档结算

建造菜单、缺料清单、仓库预约扣料和木箱快捷放置都使用当前建筑配方。蓝图一次预约整份材料。已付费的旧蓝图持有当时的预约记录，继续施工使用原预约，取消时按实付数量退回一次。已完工建筑拆除后掉落建筑物品，可拾取重放。已记录的矿格剩余量在读档与重建采集站后继续使用，最后一批只产实际余量。此前未记录余量的矿格从当前配置取初值。砍掉的整树和已掉落的木材按存档恢复。
